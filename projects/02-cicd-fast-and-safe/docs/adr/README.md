# Architecture Decision Records

Each ADR records one decision: the context, the options, what you chose, and what it cost you.

**How to use the seeded ADRs:**
1. The context and options are already written. Edit them to match *your* constraints.
2. Answer the "Questions to answer before deciding" section.
3. Write the Decision and Consequences sections, then change Status to `Accepted`.
4. If a later break-it exercise proves you wrong, **don't edit the old ADR.** Write a new one
   that supersedes it. The change of mind is the most valuable part of the story.

New ADR: copy `templates/adr-template.md` (at the root of an extracted repo, or the root of the roadmap repo).
